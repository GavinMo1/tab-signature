# 签名 · 标签页重命名

一个只面向 **Chrome 120+ 桌面版**的独立扩展。给当前标签页手动改名，或用完整网址、前缀、域名、通配符配置自动命名。无需账户、AI 接口或服务器。

## 安装

1. 下载本仓库源码 ZIP 并解压到固定目录，或克隆仓库。
2. 在 Chrome 地址栏打开 `chrome://extensions`，打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择源码中的 **`extension` 文件夹**（直接包含 manifest.json）。如果使用本地打包生成的 `tab-signature-v1.1.4.zip`，则选择解压后直接包含 manifest.json 的目录。
4. 在 Chrome 工具栏的拼图按钮中，将「签名 · 标签页重命名」固定。

安装插件不需要运行 Node，也不需要编译。此插件与「拾签」书签插件彼此独立，可以同时安装。

**从旧版更新**：将新版解压覆盖到原先加载的插件目录，在 `chrome://extensions` 点击此扩展的「重新加载」，再择机刷新使用过改名的网页。不要先移除扩展，已有规则与顺序保留；最早版本没有匹配类型的规则按“完整网址”继续生效。

**v1.1.4 稳定性更新**：复杂通配符不再使用回溯正则；域名拒绝星号；同步中发生的规则变化会补跑，冻结页面恢复后会补应用。弹窗读取中禁用操作、失败可重试，规则排序与启停保留键盘焦点。历史异常记录会标记并跳过，可单条修正/停用/删除，读取时不删除原始数据。多个管理页同时编辑时会拒绝旧快照，保留输入草稿，避免误覆盖。

安装包不包含个人规则或网站授权。拿到另一台电脑后，首次安装需要重新设置规则及授权；本版尚不支持规则导入导出。

v1.1.1 修复弹窗长时间停在“正在读取”的问题：读取不再等待所有标签页同步或网页注入，冻结页面不影响其他标签页操作，失败时显示明确提示。

v1.1.2 降低重新加载和动态页面的资源消耗：跳过休眠 / 冻结标签页，后台同步最多同时处理 3 个标签页；没有命名且没有现存脚本时不补注入。只有正在命名的页面才监听 head 和直接根节点，不监听正文变化；标题纠正合并为单个定时任务，避免与网站观察器形成微任务循环。更新后请刷新之前已打开且使用过改名的网页，让它们使用新脚本。

## 手动命名

v1.1.3 修复插件重新加载后旧脚本的 `Extension context invalidated` 未捕获错误：同步消息异常和已排队回调均检查上下文，失效时清理观察器、定时任务与事件监听。旧网页中已经运行的更早版本不能靠磁盘覆盖替换，请更新后刷新这些网页。Chrome 扩展页中的历史错误可清除，不代表新版仍在报错。

打开一个普通网页，点击插件，输入名称并「保存名称」。首次使用时允许 Chrome 请求的该网站访问权限。

- 名称只作用于当前这一个标签页；同网址的多个标签页可以分别命名。
- 刷新后保留，关闭标签页后结束。浏览器重启后不恢复手动名称。
- 网址变化后取消手动名称，包括路径、查询参数和 `#` 内容变化。
- 网站自行更新标题时，仍保持自定义名称。
- 支持中文和 emoji，最多 80 个可见字符；粘贴的换行会转为空格。
- 点击「恢复网页标题」，恢复最近观察到的网站自身标题并停止锁定。

## 自动命名规则

点击弹窗中的「设置规则」，会预填当前网址。也可点击「管理网址规则」进入管理页，新建、编辑、启停、搜索和删除规则。

- 支持下表四种匹配方式。主机名大小写、默认端口等按浏览器 URL 规则规范化。
- 规则在本机长期保存，重新打开页面或重启浏览器后仍会自动应用。
- **按列表从上到下匹配，首条已启用且命中的规则生效**，可用“上移 / 下移”调整优先级。建议将特殊页面规则放在全站规则上方；编辑不会改变顺序。
- 修改规则会更新已打开的匹配标签页；停用或删除后会使用下一条命中规则，没有其他匹配时恢复网站标题。
- **手动名称优先于规则**。同网址的多个标签页默认使用相同规则名称，可再分别手动命名。
- 点击「恢复网页标题」只让当前标签页暂时忽略规则，刷新后也保持；不会删除规则。点击「使用网址规则」可重新启用。临时忽略在关闭标签页或网址变化后结束。
- 复制标签页不会继承手动名称或临时忽略状态，会按网址重新匹配规则。

| 匹配方式 | 示例 | 生效范围 |
| --- | --- | --- |
| 完整网址 | `https://example.com/orders?env=test` | 仅这个完整地址，参数顺序、hash 也要一致 |
| 网址前缀 | `https://flow.aliyun.com/` | 此地址以及下面所有页面，可统一命名为“流水线” |
| 域名 | `flow.aliyun.com` | 此主机的 HTTP/HTTPS 页面、任意端口；不包含子域名 |
| 通配符 | `https://example.com/projects/*/runs*` | 如 `/projects/123/runs?env=test`；`*` 可匹配零个或多个任意字符 |

前缀是字面开头匹配：`https://example.com/app` 也匹配 `/apple`，只要目录下页面时请填写 `/app/`。通配符必须明确协议和域名，`*` 仅用于路径、参数或 hash，`?` 等其他字符都按字面匹配，不是正则。不同匹配方式可使用相同条件；相同方式、相同条件不允许重复保存。

## 权限与数据

安装时不要求访问所有网站；保存名称或启用规则时，按需申请目标网站权限，以便刷新和再次打开时自动改名。Chrome 的网站权限按协议和主机授权，涵盖该主机所有路径及端口；域名规则会同时申请该主机的 HTTP 和 HTTPS 权限，其他方式申请所填写协议和主机。

扩展使用标签页信息和导航事件来识别网址变化、区分标签页，使用脚本权限修改标题。本机长期存储只保存网址规则；当前标签页的手动名称与临时忽略状态使用会话存储。内容脚本不直接访问规则存储，不读取网页正文，也不上传数据、加载第三方脚本或发送统计。

可在 Chrome 的扩展详情中撤销网站访问权限。已启用但失去权限的规则会显示「需要网站授权」，重新授权后生效。删除规则不会自动撤销网站权限，因为同网站可能仍有其他规则或手动名称。

## 已知边界

- Chrome 设置页、新标签页、扩展商店、其他扩展页面和内置 PDF 阅读器等受限页面无法修改。仅支持普通 HTTP/HTTPS 网页。
- 自动命名或刷新后恢复可能短暂显示原标题；被冻结或丢弃的标签页在恢复运行后应用。
- 通过修改网页 `document.title` 命名，保留网站图标；读取网页标题的网页脚本也可能看到自定义名称。
- 停用或卸载扩展后，已打开页面可能需要刷新才能恢复原标题。
- 网站极高频率修改标题时仍可能短暂闪动；不改变网页的渲染逻辑。
- 不支持正则、跨域通配符、批量命名、跨设备同步及手动名称的跨浏览器重启恢复。

## 开发与验证

运行时源码全部在 `extension/` 中，无构建步骤。开发测试需要 Node.js 20+、本机 Google Chrome 和 Playwright 开发依赖。以下命令在仓库根目录执行：

```powershell
npm ci

npm test
npm run test:browser
npm run test:resources
npm run pack
npm run test:package
```

浏览器测试使用本机 Chrome 的全新隔离配置文件和本地网页，不操作你的真实 Chrome 配置或标签页。默认路径为 `C:\Program Files\Google\Chrome\Application\chrome.exe`，可用环境变量 `TAB_SIGNATURE_CHROME` 指定其他 Chrome 路径。测试通过 Chrome 调试协议在隔离配置中加载扩展。仅测试副本预先授权本地测试网站，以避开自动化无法可靠操作的系统权限弹窗；发布包仍然使用按需网站授权。

图标重建：`python scripts/make-icons.py`（需要 Pillow）。打包只包含插件运行文件和此说明，不包含测试、用户状态或开发依赖。
